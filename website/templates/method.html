METHOD / SKILL / DOMAIN ADAPTATION

为任何新领域，
定义一份可查询的 Survey。

Survey for AI 的交付核心是方法、Skill 与知识契约。领域术语与评价维度通过适配器更换；身份、版本、证据权限、读者路由和增量维护保留。RSI 是当前经过整理的实例，跨领域有效性仍需受控验证。

01 / SCOPE

先固定边界与读者问题。

定义操作概念、纳入排除、检索来源与截止、角色证据、比较维度、关系谓词、读者问题和预算。初始化器只创建草稿，绝不把空工作区说成完成。

02 / IDENTITY

一个工作家族，保留多个来源版本。

使用稳定 ID 组织文献，逐个保留实际 URL 与观察版本。题名相近不直接合并；歧义、旧版本和未核身份继续保留。

03 / EVIDENCE

按论文角色读取对应依据。

方法记录机制、假设与评价；benchmark 记录任务、划分和效度；理论记录定义与保证条件；综述记录覆盖与组织。正文支持才赋予相应技术主张权限，未知项不强造。

04 / FIELD MAP

树作为入口，图保留关系。

纵向发展沿有支持的技术演化连接；横向比较用有类型跨边表达。关系保留端点依据、具体谓词和边界；年代、引用与主题相似不冒充继承。

05 / READER MODULES

按纵向、横向、机制和需求综合。

每个模块声明读者目标、问题、文献、准入主张、比较条件、综合解释、限制和缺口。前沿节点绑定固定范围与截止，允许多个并列叶节点。

06 / ANSWER

先路由，后展开，答案有边界。

读者请求→问题索引→模块→主张→来源定位。需要解释时才展开解析卡或正文；返回有支持、部分支持或证据不足，附适用条件、引用和缺口。

07 / MAINTAIN

更新受影响的记录，保存真实进度。

新版本通过依赖图定位受影响主张、关系和模块；修复局部后核对全局引用。代码执行连接、哈希和检查，模型判断机制与冲突。清单最后更新，不修改门槛制造完成。

START A NEW DOMAIN可执行初始化 · 不虚构语料

从一个明确的领域开始。

python skill/survey-evidence-ledger/scripts/init_domain.py \
  --output ../my-survey --domain-id my-domain \
  --name "My field" --scope "My research question and boundaries"

完成生成的 method/domain_adapter.json 后，让 AI 读取 Skill，使用真实来源整理文献、证据和模块。通用验证器检查身份与引用，不代替科学判断。RSI 的完整网页构建与数据投影仍是实例实现。

ANSWER CONTRACT可追溯 · 可拒答

AI 收到的，不只是一个段落。

question · corpus_version · answer
claim_ids · citations {url, version, locator}
comparison_conditions · limits · gaps
status = supported | partial | insufficient_evidence

数据结构检查与方法有效性实验分开。当前没有未经测量的 token 节省或准确率提升宣称；跨领域迁移需要固定来源、同模型对照与未暴露案例测试。
