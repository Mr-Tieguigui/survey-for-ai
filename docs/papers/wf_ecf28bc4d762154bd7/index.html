1. 这项工作研究什么

在当前已核配置中，系统边界为：固定qwen-code harness内同一当前LLM充当executor、workflow optimizer和in-loop evaluator；task-specific textual workflows可写；SFT后的LLM替换下一代三role。外部strong judge仅负责reported evaluation；具体更新过程为：pairwise self-evaluation保留best workflow及feedback history，optimizer据此提下一workflow；best workflow采18 trajectories，经pairwise tournament选teacher并移除workflow提示训练LoRA；更新状态的保留与后继使用为：within-generation保留workflow/history，across-generation保留updated model weights；下一代权重同时决定执行、提出workflow及自评。

6. 局限、冲突与不能推出的结论

  • in-loop evaluator与optimizer共享prior，风险是相关自评误差；external judge仍是模型判断，非独立复现实验。
  • SFT validation为同task选出的另一trajectory，不能称task-heldout验证；test另为disjoint tasks。
  • 有限两cycle；workflow wins可尖锐反转，edit size不能预测gain，作者把每cycle加速列为未来工作。
