1. 这项工作研究什么

在当前已核配置中，系统边界为：rolling search policy及dead-end registry；具体更新过程为：元代理按round evidence重写下一轮搜索规则和经验阈值，后续workers继承策略；更新状态的保留与后继使用为：四轮campaign的策略保留。

Bilevel Autoresearch: Meta-Autoresearching Itself

关系：contrasts_system_boundary_with · r2_aevolve_training_bilevel_14 · 当前展示权限：primary_supported。 A-Evolve-Training在不可覆写substrate与只读constitution约束下，由元代理依据轮次证据重写rolling search policy、继承配方、搜索轴和dead-end registry；Bilevel Autoresearch的Level 1.5更新SearchConfig，Level 2则生成Python机制并原位修补runner.py，经动态导入检查后激活或回退。两者改变后续搜索的载体分别是策略工件和活动执行器代码。

关系边界：比较对象是明确的改进表面，不是直接继承。A-Evolve-Training只报告单次未复现的四轮、单一30B模型后训练campaign；Bilevel只证明外层改善内层，未证明同一机制反哺Level 2或无界递归。动态导入检查也不等于功能/安全性证明。

AI4AI-Bench: Benchmarking LLM Agents in Algorithmic Design for Recursive Self-Improvement

关系：contrasts_system_boundary_with · r2_ai4ai_bench_aevolve_training_17 · 当前展示权限：primary_supported。 AI4AI-Bench将开发与验证严格隔开：4小时单B300开发后只提交源代码，不传递开发权重、缓存或笔记；训练任务从初始化执行至结束或12小时上限，非训练任务一次执行后评分。A-Evolve-Training的所查四轮campaign保留rolling policy、继承配方及dead-end registry，以一个公共排行榜作为外部锚点，基底不被胜出配方覆盖。因此两者规定的跨边界持久状态和评价对象不同。

关系边界：这是评价协议与campaign证据边界的双端比较；原文没有支持AI4AI-Bench实际评测了A-Evolve-Training，不应标为evaluates。12小时是上限而非所有任务固定训练时长；不能用AI4AI-Bench的独立从头运行保障为A-Evolve campaign背书。
